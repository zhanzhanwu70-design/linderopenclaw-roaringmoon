### 六條核心命題
1. **組合規則是單點故障，而且加 agent 補不了**（2611.07140）：`θ_sys,k = θ_V,k + (1−θ_V,k)·Φ_k` → **θ_V 是系統失敗的地板**；「架構上組合規則就是單點故障，fail-safe 設計必須直接處理它；**加 agent 做不到**」
2. **多數決保護最弱的 agent，但沒有明確超過最好的那一個**：TMR [.0357,.0620]/R(10) [.5273,.6952] **未明確超過**最佳單 agent [.0005,.0361]/[.6923,.9950]（冗餘的 R(10) 下界甚至更低）；**θ_V 升到 0.05 → 風險改由 voter 驅動**
3. **γ=1 時冗餘永遠不可能比最強 agent 更可靠**（β-factor 共因分解）；γ 主要撐開**上界** → 傷害在尾部
4. **規模放大盲從，且放的比想像多**（2611.04289）：N=3→N=5 **權威凌越 +14.0→+86.0 pp（+72.0）**、多數壓力 +68.0→+100.0 pp；**多輪辯論是從眾壓力的累積器不是認知過濾器**（mitigation ignorance 72→82→95%）
5. **格式崩潰偽裝成安全**（2611.04289）：**R=3 表面不安全採納 90→23% 是假的——76.0% 的 arbiter 回應完整格式崩潰**被評為非採納；**naive anti-bias prompt 造成 81% parse error 且 ignorance 仍 81.0%**（Δ=0.00 是崩潰造成的假象）
6. **損害的形狀在傳播圖上，不在元件上**（2611.06727）：**76 個可阻止的受保護效應中只有 1 個在警報響起時已發出** → 取消已排隊呼叫擋不住；遏制＝**群組 s–t 割**（laminar max-flow 0.022–0.031 ms 解出精確割）；**比 A2A/LangGraph 多保留 +68~+96 pp 健康工作**；**不看截止期的割在 4 s 延遲下 pre-τ1 洩漏**

### 對我們最尖銳的四點
1. **我們的組合規則全是 LLM** — `sessions_send` 接收方、`conversations_turn` 回覆者、taskflow child 結果、`message` 投遞 → **每一個都是 θ_V，也都是攻擊面**
2. **fallback 必須被當成獨立失效路徑建模** — A1 案例唯一的投票失敗出現在 HTTP 503 fallback 上，而**那條路徑沒有被建模** → 我們的 503／rate limit／timeout 降級路徑目前沒有任何可靠性預算
3. **不要在 prompt 裡加「不要從眾」「要獨立思考」** — 會造成 **81% 格式崩潰**而非獨立（這是第 10 週紅線「prompt 條款不 binding」的最強版本：**不是無效，是主動製造新失效並用漂亮數字藏起來**）
4. **「尚未發出的未來效應」要能列舉** — `sessions_spawn` 子任務／taskflow 等待中的 child／cron 下一次執行 → **取消已排程的工作擋不住它們**；且遏制語意要從「擋這條訊息／停這個 agent」改成「沿傳播圖切且 deadline-aware」
