## llm-wiki nightly sync：兩個真 bug（皆已修 + 實測驗證）

### Bug 1 — rebase 後 tree 相同 → 永遠不 push（今天才暴露）
<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-roaringmoon -->
- **症狀**：腳本 rebase 成功後印 "Tree unchanged from X; nothing to push" → **4 個 commit（5204 行新內容）永遠卡在本地**
- **根因**：腳本拿 isolated index 產生的 tree 去比 `head^{tree}`；**rebase 之後 HEAD 已經含那些內容**，所以 tree 必然相同 → 誤判成「沒東西可推」
- **修法**：`tree_sha == head^{tree}` 時改成「直接 publish 既有 local commits，不建立空 commit」；且 `staged == 0` 時要檢查 `origin/main..HEAD` 是否非空
- **實測**：修完後跑真腳本 → `Tree unchanged; publishing existing local commits` → **Pushed successfully** → 遠端 2197 頁 = 本地 2197 頁，#26/#27 頁面全部上線

### Bug 2 — autostash pop 在 rebase 之後衝突 → 工作樹留下 conflict marker
- **症狀**：`DREAMS.md` 工作樹有 **8 個 conflict marker**、`memory/2026-11-09.md` 處於 unmerged（U）狀態；`git stash list` 留下 **4 個 `autostash` 殘留**
- **根因**：`git rebase --autostash` 在 rebase 結束後才套用 stash；**那次 pop 與 rebase 產生的變更衝突** → 工作樹留下 marker，且 stash 不被清掉
- **修法**：① resolver 改用 **git 的 conflict stage**（`:2:path` = ours、`:3:path` = theirs）取代 regex 解析 marker —— stage 抽取精確、不會被巢狀 marker 迷惑 ② rebase 成功後**主動檢查 autostash pop 是否衝突**並同樣解 union ③ `AUTO_UNION_FILES` 加入 `DREAMS.md`
- **實測（隔離 clone，兩個檔案都衝突 + 髒工作樹）**：4 次 union 全部成功、**三邊內容全在、0 marker**、stash 正常保留
- **清理**：已還原 `DREAMS.md`（從 origin/main，含 11-11 dream 條目，較 HEAD 多一則）、`memory/2026-11-09.md` 從 HEAD 還原；**丟掉 4 個機器 autostash**（已驗證不含 HEAD 缺的任何內容），**保留使用者自己的 stash**（08-26 那筆）
