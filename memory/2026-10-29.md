## 量測工具（本次自建，workspace 內） <!-- project: github.com/zhanzhanwu70-design/linderopenclaw-roaringmoon -->
- `research/measure_bubble.py` — 量 agent bubble rate（arXiv:2606.10662 DeLM 定義：bubble = agent wall-clock 未推進解題的時間）
- `research/extract_exchanges.py` — 從 `~/.openclaw/agents/*/sessions/*.jsonl*` 抽 `sessions_send` ↔ toolResult 配對 → `research/exchanges.jsonl`（413 筆跨 2026-05 → 10 的 agent 間交換）
- **方法論教訓（第一版量測是錯的，已修正兩次）**：
  1. 必須**以 turn 切分**（user 訊息 → assistant 最終回覆）；cron session 檔可橫跨數天，那段 idle gap **不是** bubble
  2. **平行 tool call 會重疊** → bubble 必須是 `[call_start, result_end]` 區間的**聯集**，不是加總（加總會讓 bubble% > 100%，第一版就是這樣錯的）
  3. `toolResult` 是**獨立訊息**（`role="toolResult"` + `toolCallId`），不是 content 陣列內的 item
  4. 未回傳結果的 tool（被中斷的 turn）不計入
- **實測（roaringmoon，1219 turns）**：active turn time 37.06h，tool calls 5649 / results 5647；**bubble 30.6%**（barrier >5s 本地工具 26.7%、cross-agent relay 3.0%、本地快工具 1.4%）；turn 分布 0–10% = 77.4%
- **最大單一貢獻者是我自己的 `find /home/amr/.openclaw -name ".git"`**（無 timeoutSeconds → 撞 exec 預設 1800s 上限）；`read` 585 次、`web_fetch` 494 次亦為主要來源
