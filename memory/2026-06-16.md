### runtime.py — 核心協調器（PortRuntime）

**`route_prompt(prompt, limit=5)`**
- 單一職責：把 prompt 路由到對應的 command 或 tool
- 機制：簡單的 token 重疊計分（無 ML、無 LLM）
  1. 把 prompt 切成 tokens（去掉 `/` 和 `-`）
  2. 對每個 command/tool 計算分數：name / source_hint / responsibility 中有多少 tokens 命中
  3. command 和 tool 各取最高分 1 個當 primary match
  4. 剩餘的依 score 排序後取到 limit 為止
- `_infer_permission_denials`：目前只有一個規則：`bash` 相關 tool 一律 deny，原因是「destructive shell execution remains gated」

**`bootstrap_session(prompt)`**
- 完整的 session 啟動流程：
  1. `build_port_context()` — 建立 workspace 上下文
  2. `run_setup(trusted=True)` — 跑 workspace 環境偵測
  3. `route_prompt()` — 路由
  4. `build_execution_registry()` — 建立執行 registry
  5. 執行 matched commands 和 tools
  6. `QueryEnginePort.submit_message()` — 提交給 query engine
  7. `engine.persist_session()` — 寫入磁碟

**`run_turn_loop(prompt, max_turns=3)`**
- 多輪對話迴圈，最多 `max_turns` 輪
- 每輪呼叫 `engine.submit_message()`
- 如果 `stop_reason != 'completed'` 就提前結束

### query_engine.py — QueryEnginePort（對話引擎包裝）

**職責：管理對話狀態，不做實際 LLM 推理**
- `submit_message()` — 主入口
  - 檢查 `max_turns` 上限
  - 產生 summary_lines（prompt、matched commands/tools、denials）
  - 呼叫 `_format_output()`（普通文字或 JSON）
  - 追蹤 `total_usage`（input/output tokens）
  - 檢查 `max_budget_tokens`
  - 寫入 `mutable_messages` 和 `transcript_store`
  - 觸發 `compact_messages_if_needed()`
  - 回傳 `TurnResult`

- `compact_messages_if_needed()` — sliding window 壓縮
  - 當 `len(mutable_messages) > compact_after_turns`（預設 12）時
  - 只保留最後 N 筆

- `persist_session()` → `session_store` 模組寫入磁碟
- `from_saved_session()` → 從磁碟恢復 session

- `stream_submit_message()` — generator，yield stream events
  - `message_start` → `command_match` / `tool_match` / `permission_denial` → `message_delta` → `message_stop`

**config 參數：**
- `max_turns`: 8
- `max_budget_tokens`: 2000
- `compact_after_turns`: 12
- `structured_output`: False
- `structured_retry_limit`: 2

## 對未來系統使用的影響

1. **Python Port 不等於可用的 AI Agent**：這只是 CLI 的 Python 化包裝，核心推理在 Rust。純 Python 環境無法直接使用這個 port 做自主 agent。

2. **路由機制很陽春**：token overlap 無法處理語義相似的命令（如 `/help` vs `/ask-for-help`）。未來如果要自己做 routing，不能用這個邏輯。

3. **Session compaction 是有用的設計**：sliding window 機制對話太長時自動截斷，這個模式值得參考。

4. **bash tool denial 是測試 stub**：目前的 `_infer_permission_denials` 是硬編碼的 stub，真正的權限系統在 Rust side。
