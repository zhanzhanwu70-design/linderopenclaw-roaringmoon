## ⚠️ AA payload 結構變更（已修正解析器）

舊 `tmp_aa_daily.py` 的 parse **完全失效**（parsed slugs: 0）。新版 payload 結構改變：
- model 物件改以 `{"id":"..."` 開頭，**不再**是 `"slug":` 開頭 → 舊 parser 的 `s.find('"slug":')` 找不到
- slug 移至巢狀 `release.slug`（**family 層級**），effort 變體改由 `suffix` 欄位表達
  - 例：`{"release":{"slug":"claude-fable-5-2"}, "suffix":"Max, Default Fallback", "shortName":"Claude Fable 5.2 (max)"}`
- 因此**同一 family 的不同 effort 會被誤 dedupe**（舊邏輯取最長 JSON → 抓到 null intelligenceIndex 的變體，active scored 只剩 58）

**修正：** 已直接修好 canonical 腳本 `tmp_aa_daily.py`（fetch/parse/rank）
- 新增 `build_slug()`：從 `suffix` 重建 legacy slug 方案（`family-<effort>`），**維持與舊 snapshot 的 diff 相容**
- 新增 `_extract_objects()`：改以 `{"id":"` 為物件起點做括號配對
- dedupe 品質函式改為「優先有分數者 → 再比 JSON 長度」
- `rank()` 改讀 `o['_slug']`（舊版讀 `o['slug']` 會 KeyError）
- `parse()` 在 active_scored == 0 時印 WARNING，避免靜默失敗
- 本次另寫 `tmp_diff_1115.py` 做 11/13 → 11/15 差分 + 產出 snapshot
- **驗證：** `tmp_aa_daily.py rank` 輸出與本次 diff 結果一致（Top 15 完全吻合）
- **踩到的坑**：family dedup 後再取前 N 名時，N 太小會讓前次榜尾的模型看起來像「被淘汰」（本次 N=14 → 誤判 6 個 DROP；改 N=20 後正常）
