## ⚠️ 今日教訓：平行發送會亂序（新增）
<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-roaringmoon -->
- **同一個 assistant turn 內平行呼叫多個 `message(action=send)`，落地順序不保證**。今日第一次用 4 個平行 send 發 M1–M4，Discord snowflake 顯示實際順序為 **M3 → M1 → M4 → M2**（前十 6–10 跑到前十 1–5 前面），造成分段閱讀錯亂。
- **`message(action=delete)` 在 delegated 模式下不可用**：回 `Error: Delegated discord:delete requires the exact current conversation and account for this plugin.` → 必須改用 Discord REST `DELETE /channels/<id>/messages/<id>`（token 同樣只在 process 內讀取）。
- **可行且已驗證的做法**：改走單一 python 腳本用 REST 依序 `POST`（每則間隔 0.7s 避開 rate limit），再 `DELETE` 掉亂序舊貼，最後 `GET .../messages?limit=30` 回讀比對 → 一次 run 內完成發布＋清理＋驗證，順序 100% 可控、內容逐字相符。
- **回讀比對一律以 messageId → 內容 對應**（沿用 11/21 教訓）；並額外印出「頻道實際順序」清單，讓亂序問題一次就被看見。
- 補充：`GET messages` 回傳是**新到舊**，比對順序時要反向看，別誤判成亂序。
