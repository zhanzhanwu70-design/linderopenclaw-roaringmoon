### 今日閱讀：Plugins 子系統 + ConversationRuntime

#### 1. Plugins (`rust/crates/plugins/src/lib.rs`)

**架構分層：**
- `PluginManifest` — 磁碟上的 `plugin.json` 解析後的結構
- `PluginDefinition` — 三種插件類型 `Builtin | Bundled | External`
- `RegisteredPlugin` — 加上 `enabled` 狀態的 wrapper
- `PluginRegistry` — 整個系統的插件註冊表，支援 aggregation

**核心設計亮點：**

- **Hooks 聚合 (`aggregated_hooks`)**: Registry 會把所有已啟用插件的 hooks 合併成一個 `PluginHooks`，而不是各自獨立執行。這讓 hook 可以跨插件協作。

- **Tools 衝突檢測**: `aggregated_tools()` 會追蹤已見過的 tool name，發現重名時會回傳錯誤而非 silent override。

- **三種 plugin kind 差異只在初始化行為**:
  - `Builtin`: validate/initialize/shutdown 都是 no-op（純 scaffold）
  - `Bundled/External`: 執行 lifecycle commands（Init.sh / Shutdown.sh）

- **安裝時拷貝而非連結**: `install()` 會把 plugin 目錄完整拷貝到 `install_root`，之後修改 source 不會影響已安裝的版本。

- **Stale registry cleanup**: `discover_installed_plugins()` 會檢查 registry 中的記錄是否對應實際存在的目錄，不存在的會自動移除。

- **Bundled plugin 自動同步**: `sync_bundled_plugins()` 會比對 bundled 目錄和 registry，版本/名稱/描述不同時自動更新。

---

#### 2. Hook Runner (`rust/crates/plugins/src/hooks.rs`)

**執行模型：**
- Hook 是**外部 shell 命令**，不是 Rust callback
- 透過 stdin 傳入 JSON payload（含 `hook_event_name`, `tool_name`, `tool_input`, `tool_output` 等）
- 透過環境變數也會同步設定 `HOOK_EVENT`, `HOOK_TOOL_NAME`, `HOOK_TOOL_INPUT` 等

**Exit code 语义（跟 TypeScript 版一致）：**
| Exit code | 意義 |
|-----------|------|
| 0 | Allow（工具正常執行） |
| 2 | Deny（阻止工具執行） |
| 其他 | Warn（工具執行但附帶警告訊息） |

**pipeline 順序**：所有 hook 命令串行執行，一旦遇到 Deny 就立即返回，不會執行後續命令。Warn 會累積訊息但繼續執行。

---

#### 3. ConversationRuntime (`rust/crates/runtime/src/conversation.rs`)

**核心 tool loop 流程（`run_turn`）：**

```
user_input
  ↓
API stream → AssistantMessage (含 ToolUse blocks)
  ↓
for each ToolUse:
  1. PreToolUse hook (config) → effective_input
  2. Plugin PreToolUse hook → denied?
  3. Permission check (config + prompter)
  4. 如果 denied → error tool_result
  5. 如果 allowed:
     a. tool_executor.execute()
     b. PostToolUse hook (config)
     c. Plugin PostToolUse hook
     d. merge_hook_feedback → 附加到 tool output
  ↓
loop back to API stream if more ToolUse
  ↓
break when no pending ToolUse
  ↓
maybe_auto_compact (threshold-based)
```

**Auto-compaction:**
- 依據單次 turn 的 `input_tokens`（不是 session 總 tokens）
- 閾值可透過 `CLAUDE_CODE_AUTO_COMPACT_INPUT_TOKENS` 環境變數設定
- compaction 會保留 system prompt 和最近 N 條消息，中間濃縮成摘要
- 觸發後 session 會替換，不重複觸發

**Plugin 整合方式：** 採用**裝飾器模式**，在每個 hook 呼叫點同時跑 config hooks 和 plugin hooks，各自的 feedback 都 merge 進 tool result。

**StaticToolExecutor:** Rust 版內建的 tool executor 是一個簡單的 `BTreeMap<String, Box<dyn FnMut>>`，可以透過 `register()` chain 註冊 tool handler，測試時很好用。
