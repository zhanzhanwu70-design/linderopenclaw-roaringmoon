```
$ git push --dry-run origin main

```

### 真正的機制（不是髒 tree 那麼簡單）
我第一反應是「working tree 髒 → 腳本的 dirty-guard 跳過」。實測後發現**更根本的原因**：

1. `git rev-list --count main..origin/main` = **3**（遠端有 3 個 commit 我沒有）
2. `git rev-list --count origin/main..main` = **11**（本地有 11 個 commit 遠端沒有）
3. 兩者皆非 0 → 腳本走 **`behind > 0 and ahead > 0` 的 rebase 分支**
4. 那 3 個遠端 commit 是 **`workspace-mrmime` 這第二個 clone** 推的（`backup snapshot ...`，同一個 remote `linderwu/llm-wiki`）
5. rebase 就在 **`MEMORY.md`** 上衝突 —— 因為**兩個 clone 都會改 MEMORY.md**：我這邊是每日論文 cron，workspace-mrmime 那邊是備份快照
6. 舊腳本遇到衝突 → `git rebase --abort` → 印 "Needs manual recovery" → **整次 push 跳過**

> **兩個 clone 共用一個 remote，兩邊都寫 MEMORY.md → 每晚必衝突 → 每晚必跳過。** 這是結構性問題，不是偶發。

### 五條核心命題
1. **共模失效是聚合的函數，不是個體的函數**：13 個模型、20/20 實驗中 **71.2% 的成功路徑共享同一個失效模式**；多樣化能減少相關性卻**不減少失效數量**（7.3 個體多樣化 → 仍 8 個失效模式；4.4% → 0.7%，但只抵銷 5.5%）
2. **「先到先得」會製造共模**：群體內先答對的比例 35.1% → 群體準確率反而**低於**所有個體中的最佳（35.0% vs 36.3%）；Jaccard 0.97 的貪婪聚合讓 64% 的輪次綁定同一失效模式
3. **汰換率與多樣性是獨立的旋鈕**：MMR 0.83 讓族群去相關，換掉 25% 成員（多樣化）**反而**讓共模失效率從 3.6% 升到 4.2% → **汰換 ≠ 多樣化**
4. **菁英隔離的成本曲線是非線性的**：控制共享上限 22.5% → 4.2%、28.7% → 12.0%；但 35.0% 設定的容錯**比精英隔離差**
5. **共識不是偏誤的中和劑**：共識模型與多樣化模型偏差相近（0.086 vs 0.138）；共識把弱模型拉向強模型，但也把強模型拉向弱模型的共模失敗

### 對我們最尖銳的三點
- **我們缺的不是「更多樣的模型」，是「把共模失效變成可觀察量」** —— #18 的 86.1%→89.9% 提升與我們的「子 agent 進步」敘事只差一個定義
- **信號去重必須在 evidence layer，不在 aggregation layer**（4.4% 隨機重抽能擺脫 64% 共享失效，但會抹掉 45% 真實結論）→ 這正好是 #17/#18 的 DRS 與 lineage quotient
- **分層共識不解決共模，只改變誰承擔它** —— 我們的 approval gate 屬「誰能提交」，不是「群體共識」
